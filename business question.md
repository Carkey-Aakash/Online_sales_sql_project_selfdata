# Business Questions Solved

This project uses SQL to analyze an online retail database and answer practical business questions related to customers, orders, products, sales, inventory, categories, database auditing, and performance optimization.

---

## Business Analysis Questions

### 1. Customer Order History
**Business Question:**  
Retrieve all orders and purchased products for a specific customer.

**Business Purpose:**  
Understand an individual customer's purchasing history, including their orders, products purchased, quantities, prices, and order dates.

# Database Management & Technical Tasks

The project also includes practical PostgreSQL database management and advanced SQL functionality beyond the 20 business analysis questions.

---

## 21. Database Change Auditing

**Technical Objective:**  
Create a change-log system to track INSERT, UPDATE, and DELETE operations performed on database tables.

**Implementation Includes:**

- Creating a `ChangeLog` table
- Recording the affected table
- Recording the operation performed
- Recording the affected record ID
- Recording the date/time of the change
- Recording the user responsible for the change
- Creating PostgreSQL trigger functions
- Creating triggers for database operations

---

## 22. Audit Triggers Across Multiple Tables

Change tracking was implemented for the following tables:

- `products`
- `customers`
- `orders`
- `categories`
- `order_items`

Each table includes trigger-based logging for relevant:

- INSERT operations
- UPDATE operations
- DELETE operations

This demonstrates how database triggers can automatically capture changes without requiring every application query to manually insert audit records.

---

## 23. Database Indexing & Query Performance

**Technical Objective:**  
Explore indexing and query performance optimization in PostgreSQL.

**Tasks Performed:**

- Inspect existing indexes
- Use `EXPLAIN ANALYZE`
- Create a customer-country index
- Create a product-category index
- Compare query execution behavior
- Use `CLUSTER` with a primary-key index
- Re-run queries after indexing

**Indexes Created:**

- `idx_customers_country`
- `idx_products_category_id`
